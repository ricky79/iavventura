> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** il giocatore può dare un oggetto che porta con sé a un personaggio presente («dai la corda al pellegrino»); le regole del mondo possono reagire, altrimenti il personaggio rifiuta con un testo d'autore e lo stato non cambia.

**Architecture:** un verbo nuovo `Verb.GIVE = "dai"` tra quelli sugli oggetti, con l'oggetto in `target` e il personaggio in `with`. Il motore ha un ramo `_give` che riconosce da solo quale id è il personaggio, controlla presenza e possesso, poi applica la regola o il rifiuto (`Character.refuses`). Parser, testo e interprete imparano il verbo; la Rocca non ha regole `dai`, solo il rifiuto del pellegrino.

**Tech Stack:** Python 3.12, Pydantic v2, pytest; Ollama con qwen2.5:3b per i test col modello vero.

**Spec:** `docs/superpowers/specs/2026-09-26-piu-avventure-design.md` — sezione 2.

## Decisione presa nel piano (la spec non la copriva)

«dai il miele» **senza nominare il personaggio**: lo riceve l'unico personaggio presente; se non c'è nessuno, «Qui non c'è nessuno.»; se ce n'è più d'uno, «A chi?». Lo stesso criterio di «chiedi della torre» (unico personaggio presente). Lo decide il motore, così parser e interprete non hanno casi speciali.

## Review Focus

1. **Modi di dire con «dai»** che non sono dare: «dai un'occhiata al pozzo», «dai una spinta al portone». Devono restare esamina/spingi → il parser li lascia all'LLM (test in Task 3), e il caso «dai un'occhiata al pozzo» di `test_ollama.py` deve restare verde (Task 4).
2. **«dai X» con nessuno, uno o più personaggi presenti** → risposte diverse e stato invariato quando non si dà niente (test in Task 2).
3. **Dare ciò che non si ha**: un oggetto nella stanza, un arredo, un oggetto solo in vista (la chiave nel pozzo) → «Non ce l'hai.», stato invariato (test in Task 2).
4. **Ordine rovesciato** dal parser («dai al custode la moneta») o dal modello (`bersaglio` = personaggio, `con` = oggetto) → stessa regola (test in Task 2, Task 3 e Task 4).
5. **Un autore che scrive male la regola**: `dai` senza `with`, `with` che è un oggetto, `target` che è un personaggio → problema segnalato al caricamento con percorso e id (test in Task 1).

```python
    def _give(self, state: GameState, action: Action) -> Outcome:
        """"dai X a Y": a character here receives an item the player carries. The two may come in
        either order ("dai al pellegrino la corda"); without a character, the only one here takes it.
        With no rule for it the character refuses (`refuses`), and nothing changes."""
        named = [thing_id for thing_id in (action.target, action.with_) if thing_id is not None]
        people = [thing_id for thing_id in named if thing_id in self.world.characters]
        items = [thing_id for thing_id in named if thing_id in self.world.items]
        if len(items) != 1 or len(people) > 1:
            return Outcome(ok=False, text=CANT_GIVE)
        here = [character.id for character, _ in self.characters_here(state)]
        if not people:
            if len(here) != 1:
                return Outcome(ok=False, text=GIVE_TO_WHOM if here else NOBODY_TO_GIVE_TO)
            people = here
        if people[0] not in here:
            return Outcome(ok=False, text=NOBODY_HERE)
        if state.item_locations[items[0]] != INVENTORY:
            return Outcome(ok=False, text=DONT_HAVE)
        rule = self._find_rule(Action(verb=Verb.GIVE, target=items[0], with_=people[0]))
        if rule is None:
            return Outcome(ok=False, text=self.world.characters[people[0]].refuses or NOT_WANTED)
        return self._apply_rule(state, rule)

    def _apply_rule(self, state: GameState, rule: Rule) -> Outcome:
        """The rule's text and effects, or `otherwise` when its condition doesn't hold."""
        if rule.when is not None and not holds(rule.when, state):
            return Outcome(ok=False, text=rule.otherwise or NOTHING_HAPPENS)
        for effect in rule.effects:
            _apply(effect, state)
        return Outcome(ok=True, text=rule.text)
```

```python
        return [definite(thing) for thing in things if thing not in people] + [
            articulated("a", person) for person in people
        ]
```
